| `tests/e2e/*.spec.ts` | Playwright 1.48.2, Chromium from `/ms-playwright`, flags `--enable-unsafe-webgpu --use-angle=swiftshader --enable-unsafe-swiftshader` | `slice.spec.ts` (play → move → kills → level-up → pause/resume, `errors === 0`, then the same pass with `?gl=webgl2` asserting `backend === "webgl2"`), `weapons-a.spec.ts` (the grant path in the live loop for the gun, medieval and instant kinds) and `weapons-b.spec.ts` (the alien kinds plus the heat and charge gauges, read back as `heat` / `venting` / `energy` per hand), and the two enemies specs pin the fourteen bodies through the live loop (`enemies-a.spec.ts` the melee five and `enemies-b.spec.ts` the ranged ones, both spawning rings of bodies through `__forgeDebug.spawn` and letting the real damage pass prove the result). `facing.spec.ts` is the rendering check, and it asserts on two pairs of numbers rather than on pixels: `player.shot`, the line the weapon pass gave this tick's round, read beside `player.barrel`, the line the rig is *drawn* pointing along, read back off `player.group.rotation.y` by `View.playerFace`. Each test aims at a moment where those two can disagree — a pointer parked due east, then due north, where the shipped `atan2(aimY, aimX)` reads about (0,-1) and (1,0); a chaser ring with the cursor thrown the other way, so auto-fire takes the gun off the cursor and the barrel has to follow it; the same ring with the trigger held, which a rig that merely tracks the nearest body fails; and a run with `autoFire` seeded off through `neonhorde.settings.v1`, where a cursor dragged along the mid-height band has to keep the barrel on its own round. It screenshots the same instants for a reviewer, which is what `forge-scenarios.json` is for too — the file's own rule is that pixels are never compared. `menus.spec.ts` drives the panels the way a player drives them: a dial change has to survive a reload, a rebound key has to reach the table the sampler reads, and opening Settings mid-run has to freeze the sim — all read through `__forgeState()`, with a `ready` fixture that waits for `__forgeDebug` so a poll cannot read the menu placeholder as a running game. `save.spec.ts` leaves the page: play, pause, Save, reload, Continue — the reload is the point, since a new app on a new `World` has to read the run back out of the same storage — plus the pause panel's Load and a check that an empty shelf offers no Continue, all read as `player.x` / `tick` restored within a few frames of drift and `errors === 0`. Playwright 1.48 has no gamepad emulation — its input API is keyboard, mouse, wheel and touch — so the pad has no spec here: it is pinned in `gamepad.test.ts`, which reads a `GamepadReader` fed by a plain object. `bench.spec.ts` is the frame-time half of the bench: it runs `?bench=1000&seconds=5` (and `__forgeDebug.bench(300, {seconds, chapter})` against a run already going), waits the window out, writes `test-results/bench-results.json` and reports only — no frame-time threshold, because this box has no GPU and a threshold here would measure SwiftShader. It does assert the window ran: a report exists, frames and ticks are both non-zero, the mode reads `bench`, `errors === 0`, and bodies and particles were on the floor. `death.spec.ts` (death → summary) is still open. |
| `tools/bench.ts` | `tsx`, Node, no renderer | headless sim gate: median ≤4 ms/step at 1,000 enemies over 600 ticks, non-zero exit above that |
| `src/sim/replay.ts` | a library, not a command | records one packed frame code plus its aim pair and aim distance per tick and plays them back through `step`. `serialize.test.ts` replays a recorded run whole and from a prefix and asserts the fingerprint still matches, which is what makes a divergence findable to the tick; there is no `tools/replay.ts` runner |
| `forge-scenarios.json` | root | the scenario steps and `state` assertions the Playwright specs read. A new mechanic lands with a step or assertion that fails without it. Its `save` scenario drives Save → Menu → Continue in one page, because the step vocabulary has no reload — the spec is where the cross-page round trip is pinned. Its `facing` scenario is the screenshot pair for the rig: it parks the pointer due east and due north and then holds the trigger into a wave, and it asserts `player.shot` and `player.barrel` are on one line at each stop (`aim-right`, `aim-up`, `horde`) — with the facing fix reverted, the east stop fails with the barrel at x ≈ 0.0002 while the shot is still at x = 1, which is the quarter turn caught in a number. Its viewport is 1440x900, not Playwright's 1280x720, so the two spots are measured per harness: (1330,450) is due east and (720,120) due north at 1440x900 |

Unit tests construct a `World` from a seed and feed it `InputFrame`s — no DOM, no renderer, no audio context.
Playwright specs assert on `__forgeState()`, not on pixels.

# Tests and tools

Split out of [ARCHITECTURE.md](../../ARCHITECTURE.md) — what each check pins. The commands that run them are in the [index](../../ARCHITECTURE.md).

## Tests and tools

| Path | Kind | Covers |
|---|---|---|
| `tests/unit/*.test.ts` | vitest, `environment: "node"`, no DOM | rng + spatial hash; every weapon kind (spread, pierce, falloff, reload, heat, chain, DoT); every AI behaviour (the melee five in `enemies-a.test.ts` — charger telegraphs before dashing, splitter spawns children, exploder AoE — and the ranged trio in `enemies-b.test.ts`: shooter band and 24-tick flash, grenade burst at its telegraphed ring, healer pulse, plus the enemy-round pool's i-frame gate), and the two marks in `enemies-c.test.ts` (the sniper's band and its 36-tick sight window read from both sides — a still player is hit, a player who starts moving after the line is painted is not — and the orbiter's ring held to ±15 % over five seconds of a still player and four seconds of a running one); the enemy pass's module wiring (`enemies-split.test.ts`: the dispatch table still covers every behaviour id, the travel scratch and the mending aura are each one function rather than one per module, and five whole-run fingerprints taken before `systems/enemies/` was a folder — three of them re-derived when the sniper and the orbiter joined the table, after checking that the old fixtures still reproduced their old numbers, so the guard still means "nothing about the fourteen bodies you did not change moved"); XP/level-up, powerup tiers capped at 5, dash i-frames; the chapter arc and its cover (`obstacles.test.ts`); the wave script (`waves.test.ts`: a scripted pack lands at its second and at no second before, nothing comes down inside cover or inside the 32×18 m view rect over all ten layouts, and the chapter's `hp` scale reaches the bodies); save/load round-trip; same seed + inputs → same `hashWorld`; the storage layer against a `Map` fake and a fake that throws (`persistence.test.ts`: the three keys, corrupt and partial payloads, the 50-row history cap, chapter unlocks, the autosave interval measured in play seconds); the shell's save timing (`app-save.test.ts` drives `advance(nowMs)` with no renderer and no DOM, and pins *when* the writes happen: one at 30 s of play and one per interval after it, none on the title screen, a chapter's end and a run's end each reaching the meta file, a loaded run resuming at its saved tick and playing on, and a storage that throws heard once per interval rather than per frame); the gamepad reader against a fake `Gamepad` (`gamepad.test.ts`: the radial dead zone and its rescale, held buttons read as held and pressed ones read as edges, the two face-button layouts, the merge against a held key and a projected mouse, three runs driven through `step()` (walk, shoot, take a card) and three through the headless scene machine (`createApp` with no view, no overlay and no shelf), so a pad frame has to be a frame the game plays and the shell has to hand it over); `purity.test.ts` for the import rule |
| `tests/e2e/*.spec.ts` | Playwright 1.48.2, Chromium from `/ms-playwright`, flags `--enable-unsafe-webgpu --use-angle=swiftshader --enable-unsafe-swiftshader` | `slice.spec.ts` (play → move → kills → level-up → pause/resume, `errors === 0`, then the same pass with `?gl=webgl2` asserting `backend === "webgl2"`), `weapons-a.spec.ts` (the grant path in the live loop for the gun, medieval and instant kinds) and `weapons-b.spec.ts` (the alien kinds plus the heat and charge gauges, read back as `heat` / `venting` / `energy` per hand), and the enemies spec pins the melee five through the live loop (`enemies-a.spec.ts`, which spawns rings of bodies through `__forgeDebug.spawn` and lets the real damage pass prove the splitter's split). `save.spec.ts` leaves the page: play, pause, Save, reload, Continue — the reload is the point, since a new app on a new `World` has to read the run back out of the same storage — plus the pause panel's Load and a check that an empty shelf offers no Continue, all read as `player.x` / `tick` restored within a few frames of drift and `errors === 0`. Playwright 1.48 has no gamepad emulation — its input API is keyboard, mouse, wheel and touch — so the pad has no spec here: it is pinned in `gamepad.test.ts`, which reads a `GamepadReader` fed by a plain object. `bench.spec.ts` is the frame-time half of the bench: it runs `?bench=1000&seconds=5` (and `__forgeDebug.bench(300, {seconds, chapter})` against a run already going), waits the window out, writes `test-results/bench-results.json` and reports only — no frame-time threshold, because this box has no GPU and a threshold here would measure SwiftShader. It does assert the window ran: a report exists, frames and ticks are both non-zero, the mode reads `bench`, `errors === 0`, and bodies and particles were on the floor. `death.spec.ts` (death → summary) is still open. |
| `tools/bench.ts` | `tsx`, Node, no renderer | headless sim gate: median ≤4 ms/step at 1,000 enemies over 600 ticks, non-zero exit above that |
| `tools/replay.ts` | `tsx` | replays a recorded `{seed, inputs}` log and asserts the hash matches |
| `forge-scenarios.json` | root | the scenario steps and `state` assertions the Playwright specs read. A new mechanic lands with a step or assertion that fails without it. Its `save` scenario drives Save → Menu → Continue in one page, because the step vocabulary has no reload — the spec is where the cross-page round trip is pinned |

Unit tests construct a `World` from a seed and feed it `InputFrame`s — no DOM, no renderer, no audio context.
Playwright specs assert on `__forgeState()`, not on pixels.

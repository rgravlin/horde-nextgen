# Module map

The module table, split out of [ARCHITECTURE.md](../../ARCHITECTURE.md). The index keeps the rules, the [data flow](data-flow.md) the runtimes and the [tests](tests.md) where each check lives.

## Module map and allowed imports

| Module | Owns | May import |
|---|---|---|
| `src/content/` | typed data only: `weapons.ts`, `enemies.ts` + `enemiesA.ts` (the archetype table, split by hand rather than by kind: `ENEMIES` spreads `ENEMIES_CORE` and `ENEMIES_A` and is the only name anyone imports, so a new chapter of bodies arrives in a new file), `powerups.ts`, and `levels/` (the chapter table, split the same way: `chapters-1-3.ts` + `chapters-4-6.ts` + `chapters-7-10.ts` in play order, joined and clamped by `index.ts`, which is also where a chapter's elite roster gets resolved against `elites.ts`; the `LevelDef` schema is in `types.ts` and the floor, script and tint shorthands every chapter file is written with are in `builders.ts`). A table's schema lives beside it (`weapons.ts`, `enemies.ts`, `powerups.ts`, `levels/types.ts`), never in a shared types file | nothing but the `sim` ids it shares (`PropKind`/`ZoneKind`, `EdgeId`) |
| `src/sim/` | `world.ts` (`World` and `createWorld`, plus the re-export of the three modules cut out of it so the sim, the render layer and the tests still come in through one door: `pools.ts` — the struct-of-arrays pool and its `alloc`/`release`/`countAlive`; `constants.ts` — the pool caps, the tuning in one `TUNE` and the `Ev`/`Tele` event ids, each written down once; `events.ts` — the event ring and the blast stack), `step.ts` (system order), `input.ts` (the `InputFrame` type), `rng.ts` (xoshiro128**), `spatialHash.ts`, `hash.ts`, `systems/{weapons,status,enemyProjectiles,pickups,waves}.ts`, `systems/projectiles/` (the shot physics: `shared.ts` holds the one way a hit lands and the padding every query uses, `ray.ts` the hitscan, beam and chain marches, `melee.ts` the arc sweep, `flyers.ts` everything a round does while it is in the air — flight, `steer`, `drag` and `burst`), `systems/enemies/` (the enemy pass: `shared.ts` holds the drive and the tick's travel scratch plus the one findability fact the whole tick reads — `underground(phase)` and the `markFindable` pass that refills `hash.findable` before `step.ts` rebuilds the grid, so a body under the floor is in no query at all rather than excepted in thirteen places, then one module per movement family — `seekers.ts`, `rushers.ts`, `standoff.ts`, `support.ts`, `marksmen.ts` (the sniper and the orbiter, which share one bargain: a line is painted, held, then spent along it), `burrowers.ts` (the same bargain crossed under the floor: untargetable while it travels, a ring for its burst, both halves pinned in `tests/unit/enemies-e.test.ts`), `bosses.ts` — plus `spawn.ts`, `update.ts`, `behaviours.ts`, `contact.ts` and `deaths.ts`), `systems/obstacles.ts` (the one cover + floor-hazard path: swept circle-vs-box and circle-vs-circle push-out, and the hazard clocks), `systems/levels.ts` (the chapter arc: which floor is under the player, and what its script ends on), `serialize.ts` (the save: whole pools and the floor as bytes, scalars as numbers), `replay.ts` (records a run's input and plays it back), later `config.ts` | `src/content` only |
| `src/render/` | `renderer.ts` (WebGPURenderer + `renderer.init()`, backend probe, the camera rig and the `RenderPipeline` chain: bloom → chromatic → ACES), `instancing.ts` (one `InstancedMesh` per look: archetype bodies and cores, rounds, shards, the dash trail), `meshes/` (the procedural geometry and materials those batches draw: `primitives.ts` — the part-merge toolkit and the triangle-count readout, `shapes.ts` — the archetype recipes keyed by mesh id and their cache, `shapesC.ts` — the three recipes keyed by archetype instead (teleporter, burrower, spawner), spread into `SHAPES` so they come through `hordeMesh` like the rest, `props.ts` — the projectile, player-kit and telegraph shapes, `materials.ts` — the three materials and the two per-instance flash/dissolve attributes; the folder comes in through its `index.ts`, so the callers still import `./meshes`), `scenery.ts` (the floor's hazard discs), `telegraphs.ts` (the Threat Red charge strips, landing rings and sniper sights), `fxView.ts` (the instanced particle fields), `lights.ts` (the pooled point lights), `assets.ts` (the concrete floor, the Kenney kit cover and the HDRI environment). The quality tier is read by `assets.ts`, `lights.ts`, `instancing.ts` and `renderer.ts`, which is where the Low/Med/High knobs live. | `three`, `three/webgpu`, `three/tsl`, read-only `sim`/`content` |
| `src/audio/` | `synth.ts` (WebAudio graph), `sequencer.ts` (the music clock), `songs.ts`, `sfx.ts` (event id → voice) | read-only `sim` events; no engine import |
| `src/ui/` | `hud.ts` (the corner readouts, the boss plate and the edge markers), `radar.ts` (the top-left map, painted on one 2D canvas), `levelup.ts` (the three-card offer), `menus.ts` (the screen panels), `styles.css` (DESIGN.md palette/type scale for the whole overlay) | read-only `sim`/`game` state; no engine import |
| `src/input/` | `sampler.ts` (keyboard + mouse + pad → `InputFrame`), `gamepad.ts` (the polled pad: two dead-zoned sticks, edge-tracked buttons, one of two face-button tables per frame), `bindings.ts` (default map, remappable — pads are not in it) | `sim` types and `sim` constants only |
| `src/game/` | `app.ts` (scene state machine, and the save timing hung off it: `archiveRun`, the `save`/`load` commands, Continue), `loop.ts` (fixed-step accumulator), `persistence.ts` (the three storage slots: run, settings, meta; plus the autosave clock), `debugState.ts` (`__forgeState`) | `sim`, `content`, `input`, and the render/audio/ui modules |
| `src/main.ts` | composition root: build the `World`, the renderer, audio, UI and input, register `window.__forgeState` / `window.__forgeDebug` | everything |

Hard rules, checked in CI:

- `tests/unit/purity.test.ts` greps `src/sim/**` and `src/content/**` for `three`, `document`, `window`,
  `localStorage`, `performance.now` and timer calls and fails on any hit.
- `render`, `audio` and `ui` never import each other and never write to the `World`; they only consume it. Only
  `src/sim/` mutates game state; `src/game/` and `src/input/` feed it.
- `src/audio` and `src/ui` must not import from `src/render` — a headless run with rendering disabled still plays
  sound and updates the HUD.
- Anything touching `window` or `localStorage` goes through a port (`StorageLike`, `Clock`) injected from
  `main.ts`/`game`, so unit tests pass in-memory stubs and Node stays green.
